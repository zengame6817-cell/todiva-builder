# 全員共通の画像設定を有効にする

サイトはGitHub Pagesのままです。画像調整と差し替え画像だけをSupabaseへ保存します。手持ち・戦力・お気に入り・ビルド・バックアップは送信しません。

## 1. Supabaseのプロジェクトを作る

https://supabase.com/dashboard を開き、サインアップまたはログインします。「New project」でプロジェクトを作成します。名前は `todiva-builder` など。データベースのパスワードは自分で設定・保管してください。作成後に使う接続キーとは別物です。

## 2. データベースを準備する

プロジェクトの「SQL Editor」で新しいクエリを開き、このフォルダーの `supabase/shared-images.sql` の内容をすべて貼り付けて実行します。

この設定では全利用者が画像の最新版と履歴を閲覧し、対応するカードの画像設定を更新できます。手持ちなどの個人データは対象外です。変更履歴は各カードの最新30件を保持します。以前の設定へ戻す操作も新しい履歴として保存されます。

## 3. 接続情報を設定する

プロジェクトの接続情報からProject URLとPublishable keyを取得します。APIキーはSettings → API Keysで確認できます。`sb_publishable_` で始まる公開用キーを使います。

`dist/data/shared-images-config.json` を次のように編集します。

```json
{
  "enabled": true,
  "url": "https://プロジェクトID.supabase.co",
  "publishableKey": "sb_publishable_で始まる公開用キー"
}
```

URL末尾の `/` は付けません。データベースのパスワード、Secret key、service_roleキーはこのファイルには入れません。

## 4. GitHubのサイトを更新する

更新版の `dist` をGitHubリポジトリにアップロードします。Actionsの公開処理が成功した後にサイトを開きます。既存の `.github/workflows/pages.yml` はそのまま使います。

画像の詳細 →「画像を調整」に「全員共通の画像として保存」が表示されます。通常の「調整を保存」なら接続がまだ無効です。

## 5. 別のブラウザで確認する

1つのブラウザで調整・保存し、もう1つでサイトを再読み込みして同じ構図になることを確認します。既存のローカル設定より共有設定を優先します。他の人の変更は再読み込み・画像調整画面を開いたとき・画面に戻ったとき・通常表示中の定期確認で取得します。編集中の画面は更新で上書きしません。

「共有画像の変更履歴」で以前の設定へ戻せます。「元の画像・表示に戻す」は、共有が有効な場合には全員の表示をアプリの標準構図へ戻す操作です。他の人が先に保存した場合は衝突を表示するので、調整画面を開き直してください。

設定を無効にする場合は `enabled` を `false` にしてサイトを更新します。共有データはSupabaseに残ります。
